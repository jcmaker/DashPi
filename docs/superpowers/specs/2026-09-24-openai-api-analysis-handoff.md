# DashPi AI 분석 백엔드 결정 핸드오프

**날짜:** 2026-09-24

**상태:** OpenAI API 사용 결정. 구현 설계와 코드 변경은 아직 하지 않음.

## 결정된 범위

- Raspberry Pi 5의 영상 기반 사고 분석 백엔드는 Pi에서 Ollama 모델을 실행하는 방식 대신 OpenAI API를 사용하는 방향으로 전환한다.
- Pi 네이티브 앱의 카메라 녹화, 수동 **사고 분석** 트리거, 트리거 전 30초·후 15초 수집, 증거 영상의 로컬 보존, 리포트 표시와 광학 QR 전송 흐름은 유지한다. 마이크·GPS·배터리 센서는 추가하지 않는다.
- 이 결정은 [기존 네이티브 앱 설계](2026-09-24-native-pi-app-design.md)와 [구현 계획](../plans/2026-09-24-native-pi-app.md)의 **로컬 Ollama 분석 백엔드** 부분만 대체한다. API 연동 방식의 세부 설계나 배포 승인을 뜻하지 않는다.

## 결정 근거와 현재 상태

- 실물 Pi는 RAM 4GB다. `gemma3:4b`로 실제 영상을 분석했을 때 메모리 부족으로 실패했다. `granite3.2-vision:2b`는 이미지 크기·프레임 수·컨텍스트를 줄이면 리포트 형식을 통과했지만, 4프레임 분석도 수분이 걸렸다.
- 현재 앱은 여전히 [`OllamaClient`](../../../src/dashpi/reports.py)를 사용한다. 사고 파이프라인은 프레임 추출 뒤 분석 함수를 호출하고 결과 형식을 검증한다. Pi의 저장된 모델 설정도 이 문서로 변경되지 않는다.
- **이번 핸드오프는 문서만 변경한다.** API 호출, API 키 설정, 영상 업로드, Pi 배치 또는 기존 Ollama 제거는 하지 않는다.

## 구현 전에 결정할 사항

1. 주행 중 인터넷이 없는 경우의 상태와 재시도 방식. 녹화와 증거 보존은 네트워크에 의존해서는 안 된다.
2. OpenAI의 영상 입력 지원 모델, 전송할 자료의 범위(영상 전체 또는 추출 프레임), 프레임 수·해상도, 목표 지연 시간과 품질 평가 기준.
3. API 키의 안전한 보관·교체 방식과 사용량/비용 상한. 키를 저장소에 커밋하지 않는다.
4. 번호판·얼굴이 포함될 수 있는 영상의 외부 전송 고지와 개인정보 처리 방침. 리포트는 기존 검증을 통과한 뒤에만 표시·전송한다.

OpenAI 공식 문서에 따르면 Responses API는 한 요청에 여러 이미지 입력을 받을 수 있고 이미지 입력은 토큰으로 과금된다([Images and vision](https://developers.openai.com/api/docs/guides/images-vision)). API 입력은 기본적으로 모델 학습에 사용되지 않지만, 보안 모니터링 로그의 기본 보존 정책은 별개다([Data controls](https://developers.openai.com/api/docs/guides/your-data)).
