# DashPi 증거 우선 사고 분석 리포트 설계

**작성일:** 2026-10-02
**상태:** 승인됨
**범위:** Raspberry Pi AI 분석 결과와 광학 전송 후 모바일 리포트 화면

## 1. 목표

DashPi는 보존된 45초 사고 영상 전체를 분석하고, 사고 순간을 중심으로 전후 10초 영상과 구조화된 분석 결과를 하나의 HTML 리포트로 휴대폰에 전송한다. 모바일 리포트는 증거 영상을 먼저 보여주는 B형 레이아웃을 사용한다.

리포트는 영상에서 관찰된 사실과 확인할 수 없는 내용을 분리한다. 법적 과실과 12대 중과실 해당 여부를 판정하지 않는다.

## 2. 확정 제약

- Raspberry Pi 5와 전방 카메라만 사용한다.
- GPS, 차량 속도, CAN, IMU, 음성 데이터가 없다.
- 원본 증거 영상은 사고 표시 전 30초와 후 15초를 합친 45초이다.
- AI 분석은 45초 전체 구간을 대상으로 한다.
- 광학 전송 영상은 사고 순간 기준 전후 10초만 사용한다.
- 119와 112는 일반 텍스트로 표시하며 전화 연결, `tel:` 링크, 통화 버튼을 제공하지 않는다.
- 현재 `DPQ1`/`DPC1` 광학 규격과 단일 HTML 파일 전송 방식을 유지한다.
- AI는 속도, 충격량, 음주, 면허 상태, 법적 책임을 추정하지 않는다.

## 3. 접근 방식

### 선택: Pi가 완성된 HTML을 생성하고 모바일 앱이 WebView로 표시

Pi가 구조화된 AI 결과와 전후 10초 영상을 이용해 모바일용 HTML을 완성한다. 모바일 앱은 현재와 같이 무결성을 검증한 뒤 HTML을 WebView에서 표시한다.

이 방식은 저장·공유된 HTML에서도 동일한 리포트를 볼 수 있고, 광학 프로토콜과 모바일 저장 구조를 변경하지 않는다.

### 제외한 방식

- JSON과 영상을 별도로 보내 네이티브 화면을 구성하는 방식: 단일 파일 컨테이너와 수신·저장·공유 흐름을 모두 바꿔야 한다.
- HTML 내용을 모바일 앱이 다시 파싱하는 혼합 방식: 동일 정보를 두 번 렌더링하며 실패 지점만 늘어난다.

## 4. Pi 분석 흐름

1. 현재처럼 45초 원본 `clip.mp4`를 변경 없이 보존한다.
2. 45초 전체에서 균등하게 뽑은 기존 표본 프레임으로 사고 순간을 찾는다.
3. 사고 순간 전후의 고밀도 프레임을 추가로 추출한다.
4. 전체 구간 표본과 사고 주변 고밀도 표본을 시간순으로 합치고 중복 시각을 제거한다.
5. 합친 프레임을 한 번의 관찰 단계에 전달해 45초 문맥과 사고 순간의 세부 정보를 함께 분석한다.
6. AI는 시간별 사실, 요약, 한계, 12대 중과실 관련 영상 확인표를 구조화해 반환한다.
7. Pi는 사고 순간 전후 10초 파생 영상을 만들고 HTML 리포트에 포함한다.

여기서 “45초 전체 분석”은 45초 영상의 모든 프레임을 모델에 보내는 의미가 아니다. 전체 구간의 균등 표본과 사고 주변 고밀도 표본을 함께 분석하는 방식이다. 이 한계는 리포트에 표시한다.

## 5. AI 출력

### 시간별 관찰

각 관찰은 다음 필드를 가진다.

- `timestamp`: 45초 클립 시작 기준 시각
- `description`: 영상에서 직접 관찰되는 사실

화면에서는 사고 순간을 `0.0초`로 바꿔 `-2.1초`, `+1.4초`처럼 표시한다. 사고 순간 전후뿐 아니라 45초 전체에서 사고 이해에 필요한 관찰을 포함할 수 있다.

### 요약과 한계

- `summary`: 관찰 목록만 사용한 짧은 사고 요약
- `limitations`: 가림, 야간, 낮은 화질, 표본 프레임 분석, 화면 밖 상황처럼 확인을 제한한 요소

AI는 관찰에 없는 숫자, 속도, 차량 상태, 사람의 의도, 법률 판단을 추가하지 않는다.

### 12대 중과실 관련 영상 확인표

Pi는 다음 12개 항목을 고정된 순서로 출력한다.

1. 신호 지시 관련 장면
2. 중앙선 관련 장면
3. 제한속도 초과 여부
4. 앞지르기·끼어들기 관련 장면
5. 철길건널목 관련 장면
6. 횡단보도 보행자 관련 장면
7. 운전면허 상태
8. 음주·약물 상태
9. 보도 침범 관련 장면
10. 승객 추락 방지 관련 장면
11. 어린이보호구역 관련 장면
12. 화물 고정 관련 장면

각 항목의 상태는 다음 세 값만 사용한다.

- `영상에서 관련 장면 관찰됨`
- `영상에서 관련 장면 관찰되지 않음`
- `영상만으로 확인 불가`

각 상태에는 근거 문장과, 존재할 경우 클립 기준 시각을 붙인다. `해당`, `비해당`, `위반`, `무혐의`, `과실`이라는 판정 표현은 사용하지 않는다.

속도, 면허, 음주·약물처럼 카메라만으로 확인할 수 없는 항목은 항상 `영상만으로 확인 불가`로 정규화한다. 어린이보호구역은 표지 관찰 여부만 기록하며 구역 여부와 상해 발생을 확정하지 않는다.

## 6. 모바일 B형 레이아웃

광학 수신과 SHA-256 검증이 끝나면 앱은 별도 다운로드나 저장 선택을 요구하지 않고 리포트를 즉시 표시한다. 앱 종료나 화면 이탈에 대비한 앱 전용 저장소 기록은 사용자에게 보이지 않게 수행할 수 있지만, 외부 파일 다운로드·공유·저장은 미리보기 뒤의 선택 동작이어야 한다.

리포트는 다음 순서로 표시한다.

1. **사고 기록 헤더**
   - 사고 발생 절대 시각과 시간대
   - `SHA-256 무결성 검증 완료`
2. **사고 전후 10초 영상**
   - 사고 순간 위치를 영상 타임라인에 표시
3. **대표 이미지 세 장**
   - 사고 전, 사고 순간, 사고 후
4. **AI 핵심 요약**
5. **사실 타임라인**
   - 사고 순간 기준 상대 시각과 관찰 문장
6. **확인할 수 없는 내용**
   - AI 한계와 센서 부재로 측정할 수 없는 항목
7. **12대 중과실 관련 확인 항목**
   - 기본은 접힌 상세 영역
   - 법적 판단이 아닌 영상 사실 정리라는 설명을 제목 바로 아래 표시
8. **긴급 번호**
   - `119 · 구급/소방`
   - `112 · 경찰`
   - 탭 동작이 없는 일반 텍스트
9. **증거 상세**
   - 사고 ID, 생성 시각, 사용 모델, 원본·파생 영상과 대표 이미지의 SHA-256

모바일 앱의 기존 `공유 또는 파일에 저장`, `저장본 삭제`, `새로 받기` 동작은 HTML 밖의 네이티브 영역에 그대로 둔다.

수신 완료 화면의 순서는 `리포트 미리보기` → `검증 완료 상태` → `공유 또는 파일에 저장`이다. 다운로드 안내, 저장 위치 선택, 공유 시트는 사용자가 미리보기를 보기 전에 열리지 않는다.

## 7. 안전 및 신뢰성

- 원본 45초 영상은 분석 전후 SHA-256이 같아야 한다.
- 전송된 HTML은 기존 DPC1 SHA-256 검증을 통과한 뒤에만 열린다.
- 파생 영상과 대표 이미지는 원본 증거와 명확히 구분한다.
- 객체 탐지나 AI 분석 일부가 실패하면 해당 섹션에 실패 사실을 표시하고 원본은 보존한다.
- 리포트 상단에는 과실이나 법적 책임을 판단하지 않는다는 긴 경고를 배치하지 않는다. 관련 설명은 분석 한계와 12대 중과실 확인표 안에서 필요한 시점에 보여준다.

## 8. 호환성

- 기존 리포트 JSON의 `incident_timestamp`, `summary`, `observations`, `limitations` 필드는 유지한다.
- 새 12대 중과실 확인표는 새 필드로 추가한다.
- 과거 HTML 리포트는 모바일 앱에서 계속 열린다.
- 모바일 앱은 리포트 스키마를 직접 해석하지 않으므로 네이티브 데이터 마이그레이션이 필요 없다.

## 9. 검증

최소 자동 검증은 다음을 포함한다.

- 관찰 단계가 45초 전체 표본과 사고 주변 표본을 시간순으로 전달하는지 확인
- AI 출력에서 속도·음주·면허가 `영상만으로 확인 불가`로 정규화되는지 확인
- 12개 확인 항목이 누락되거나 추가되지 않는지 확인
- 요약과 타임라인이 HTML 이스케이프되는지 확인
- HTML 섹션이 B형 순서로 배치되는지 확인
- 119와 112가 표시되지만 `tel:` 링크가 없는지 확인
- 검증된 HTML이 다운로드나 공유 동작 없이 즉시 미리보기 모델로 열리는지 확인
- `공유 또는 파일에 저장` 동작이 미리보기 뒤에만 제공되는지 확인
- 전송 영상이 사고 순간 전후 10초로 유지되는지 확인
- 원본 영상의 SHA-256이 분석 전후 동일한지 기존 검증 유지
- 기존 모바일 수신·저장·공유 테스트와 Pi 전체 테스트 통과

## 10. 완료 조건

- Pi가 45초 전체 문맥과 사고 주변 세부 프레임을 함께 분석한다.
- 휴대폰에서 영상이 첫 번째 주요 콘텐츠로 보인다.
- 시간별 사실과 확인 불가능한 내용이 분리되어 보인다.
- 12대 중과실은 법적 판정 없이 영상 확인표로 제공된다.
- 119와 112는 번호 안내로만 표시된다.
- 수신 완료 후 저장 요구 없이 리포트가 먼저 표시되고, 외부 저장과 공유는 선택 사항으로 남는다.
- GPS, 속도, 충격량이 생성되거나 추정되지 않는다.
- 현재 광학 전송과 저장·공유 기능이 그대로 동작한다.
